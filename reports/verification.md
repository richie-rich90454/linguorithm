# Development verification

Environment: Windows x64 with the project-contained Node runtime, Python environment, dependencies, model assets, and browser binaries. Project workflows are exposed through GNU Make targets; this session's Make executable could not initialize, so the same project-local task runner invoked by the Makefile was used for verification.

- `check` passes lint, formatting, strict TypeScript, and 302 engine tests across 19 files.
- The full serial release browser suite passes all 192 Playwright checks across Chromium, Firefox, WebKit, and mobile Chromium emulation. Coverage includes actual local-model inference, feature parity, modal and passive controls, offline reload, document persistence and restore, import security, keyboard access, responsive layouts, count-noun review and numeric identifier controls, optional goal-cue display, and learner-controlled corrections.
- Content validation passes for 106 authored and verified-mutation exercises. The model release check verifies all 18 model resources, clean restoration, repair of a changed asset, and rejection of a corrupt archive.
- The production build succeeds. Initial JavaScript is 84.2 KiB gzip against the 104.7 KiB budget; secondary views and the analysis worker are lazy-loaded. Runtime model inference and document analysis remain local.
- Shipped full EWT component evidence remains 94.47% POS, 81.66% UAS, and 77.27% LAS across 1,962 sentences / 24,859 tokens. Candidate weights remain unpromoted.
- The current browser regression report measures 93.50%/81.91%/77.81% POS/UAS/LAS over 300 EWT sentences / 3,659 gold tokens. It aligns 3,610 tokens and exactly tokenizes 266 sentences. The sample spans five source genres and counts unmatched tokens as incorrect. It was inspected during tokenizer development, so it is not an untouched confirmatory test.
- The fixed browser scores improve 1.31/1.75/1.72 absolute points over the original POS/UAS/LAS baselines, below the requested five-point floor. The candidate's full EWT scores improved by 0.19/0.75/0.70 points, but its fixed browser POS and LAS scores declined; it did not pass the no-regression gate. The full EWT parser goals and the million-token POS claim remain unmet.
- The goal catalog contains exactly 100 general writing goals, all connected to registered local detector IDs: 32 goals have narrow diagnostic patterns only, 67 have optional evidence cues only, and cohesion has both. Every cue rule runs through fallback and model-backed analysis, emits a source-linked review prompt, and provides no correction. The regression suite verifies goal and cue registration; controlled fixtures show wiring, not independent accuracy. No detector has independent evidence meeting the requested precision, recall, valid-control, and correction-acceptability gates. These statuses describe connection only, not quality certification or learner mastery. The count-noun plural rule still abstains on numeric identifiers governed by an indefinite article, and the gerund-complement rule still requires its narrow stable neural parse; both withhold edits.
- On the 63 controlled agreement mutations, the complete hybrid detects 53 and misses 10, with zero target false positives on 63 source controls; classifier-only findings detect none. On 26 authored clean probes, there are zero conservative false positives and one review warning. These authored and synthetic checks do not establish learner-writing accuracy.
- The latest generalization run checks source/edit integrity on all 411 cases and 229 proposed edits. Correction integrity verifies source spans and edit transactions; it does not establish that a proposed change preserves meaning.

Full benchmark methods, intervals, per-genre results, model provenance, and remaining limitations are recorded in the [model card](../docs/model-card.md), [release gates](../docs/release-gates-2026-10-24.md), and [reproducible report](generalization.json).
