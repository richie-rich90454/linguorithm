## Detector precision cleanup · 2026-10-27

The detector now accepts common British spelling variants of packaged American forms, abstains from parsed fragment reviews when “after/before/since that” introduces a temporal adjunct, anchors a fragment finding to its subordinating marker instead of the whole sentence, excludes relative “that” from parsed subject–verb agreement, and expands the curated direct-correction misspelling list. `make check` passed lint, formatting, strict TypeScript checks, and 346 engine tests across 22 files.

The fixed production-browser evaluation was rerun once on the unchanged 184-document test split. Counts are TP 110, FP 475, FN 3,907, and TN 56,333 (60,825 tokens). Precision is 18.80% (Wilson 95% CI 15.84–22.17%), recall 2.74% (2.28–3.29%), F0.5 8.65%, total token misclassification 7.204%, missed-error rate 97.26%, and false-positive rate 0.836% (0.765–0.914%). The previous frozen run had 128 TP, 688 FP, 3,889 FN, 15.69% precision, 3.19% recall, 7.52% total error, and 1.211% false-positive rate. The cleanup therefore removed 213 unannotated findings and 18 true positives: precision rose 3.11 points, total error fell 0.32 points, and false-positive rate fell 0.375 points, while recall fell 0.45 points.

The latest requested limits are at least 50% precision, at most 5% total token misclassification, and false-positive rate below 1.21%. The false-positive limit now passes; precision and total error do not. The report also records the exact feasibility consequence: at exactly 50% precision, false positives equal true positives, so total errors equal the 4,017 gold tokens (6.604%). The 5% limit requires precision above 56.91% even at perfect recall, or 97.24% at 25% recall; the current run has 365 fewer true positives than false positives and needs 1,341 more net correct detections. These aggregate corpus-overlap measures do not establish goal-specific precision, valid-control behavior, or correction acceptability. No model weights changed.

On the unchanged development split (198 documents, 70,165 tokens, 4,721 annotated-positive tokens), the updated detector has TP 141, FP 530, FN 4,580, and TN 64,914: precision 21.01%, recall 2.99%, total error 7.283%, and false-positive rate 0.810%. The previous development baseline was TP 165, FP 722, FN 4,556, TN 64,722: 18.60% precision, 3.50% recall, 7.522% total error, and 1.103% false-positive rate. The development split was used for the cleanup analysis; the fixed test split was scored once after the code was frozen.

## Unrecognized repair responses · 2026-10-27

The app saves the learner's text for review without attaching a fabricated answer index, excludes it from mastery and assessment accuracy, and shows one verified example with the rule so a learner can compare without being told that a different valid sentence is wrong. ## REALEC token-classifier experiment · 2026-10-27

A project-local, development-only experiment trained a sparse token classifier on the document-separated REALEC training documents using token spelling, character affixes, and neighboring word and punctuation features. The classifier was scored against the unchanged 198-document development split (70,165 tokens; 4,721 annotated-positive tokens), using the browser evaluator's tokenizer. It was not merged with production findings, exported as a model, or evaluated on the fixed test split. This experiment tests whether more of the available corpus labels can be recovered with local supervised learning; it does not validate correctness against independent expert labels.

The best-recall threshold with false-positive rate below 1.21% found 258 of 4,721 annotated tokens (5.46% recall), with 788 false positives, 4,463 false negatives, 24.67% precision, 7.48% total token misclassification, and 1.204% false-positive rate. A threshold with 50% precision detected only 18 true positives and 18 false positives (0.38% recall), leaving 6.73% total token misclassification. The latter improves the aggregate error rate mostly by abstaining on nearly all tokens, so it is not useful tutoring coverage.

On this split, satisfying all three requested limits requires at least 2,004 true positives (42.45% recall), at most 791 false positives, and at most 3,508 total token errors. The experiment reached 258 true positives under the false-positive ceiling. It therefore fails the requested combination by a wide margin and was rejected. The held-out test remains untouched; production behavior and model assets remain unchanged. This confirms that another generic token-classifier threshold sweep is not a viable fix. Progress requires error-specific, writer-separated labels with adjudicated valid controls and usable correction targets; the current corpus includes broad discourse and wording annotations, lacks author identities, and does not establish that every annotation is a correctness error.
