## No-regression detector guard · 2026-10-27

A precision-first cleanup (British spelling variants, marker-only fragment spans, and relative-“that” agreement exclusion) reached 18.80% precision and 0.836% false-positive rate on the fixed test, but recall fell from 3.19% to 2.74%. That candidate was reverted because no metric regression is allowed.

The retained changes are a temporal “after/before/since that” guard for parsed fragment reviews and an expanded curated misspelling list. The fixed test result is unchanged: TP 128, FP 688, FN 3,889, TN 56,120; 15.69% precision, 3.19% recall, 7.525% total error, and 1.211% false-positive rate. The guard did not change the fixed test counts.

On the development split, the guard removes 32 false positives with no true-positive change: TP 165, FP 690, FN 4,556, TN 64,754; 19.30% precision, 3.50% recall, 7.477% total error, and 1.054% false-positive rate. The previous development result was 18.60%, 3.50%, 7.522%, and 1.103%, so all four fields improve or remain equal.

The latest request (at least 50% precision, at most 5% total error, below 1.21% false-positive rate) remains unmet on both splits. The report's feasibility section shows that at exactly 50% precision total error equals the gold error count (6.604%). A 20x increase in test true positives would require about 2,560 true positives while holding false positives at or below the current 688 — roughly 64% recall at 79% precision. Rule tuning has not approached that operating point; production-grade justification requires a materially stronger objective-error model and/or a writer-separated corpus with adjudicated controls.

A benchmark contamination audit found that 5 of the 184 fixed-test documents (9,312 tokens and 569 gold tokens, 14.2% of test gold) have an exact or near-duplicate in train/development, using word 5-gram Jaccard similarity at or above 0.9; one is an exact duplicate. A model can therefore memorize part of the test from training. The transfer upper bound is 569 additional true positives. Even if all 569 were new and added no false positives, the fixed test would reach TP 697, FP 688, precision 50.3%, recall 17.3%, total error 6.59%, and false-positive rate 1.211%. That still fails the 5% and 1.21% limits. The fixed split should be deduplicated before any independent generalization claim; the official report is unchanged because the split is frozen.

A parser-feature MLP candidate was trained on 291,580 retained REALEC training tokens using frozen POS, dependency relation, head distance, morphology, character features, and an internal document holdout. It was rejected: on 58,385 retained development rows, the max-net threshold found 24 TP and 46 FP (34.3% precision, 0.6% recall); the best-recall threshold under the false-positive ceiling found 146 TP and 609 FP (19.3% precision, 3.65% recall, 7.64% error on retained rows). No threshold reached 50% precision. The candidate is not integrated; the detail is in [realec-context-model.json](realec-context-model.json).

Two mature browser-runnable, non-LLM grammar engines were also tested locally on the first 20 development documents with the evaluator tokenizer. Harper.js 2.13.0 (Apache-2.0) produced TP 77, FP 516, FN 323, TN 4,415: 12.98% precision, 19.25% recall, and 10.46% false-positive rate; its Readability and Style spans accounted for most false-positive tokens. LingoTweaker 0.2.8 (LGPL-2.1-or-later, LanguageTool rules) produced TP 38, FP 153, FN 362, TN 4,778: 19.90% precision, 9.50% recall, and 3.10% false-positive rate; its Grammar category found 3 true positives and 5 false positives. Neither beat the production rules, so both dependencies were removed. `make check` passed 344 engine tests, the Playwright suite passed 204 checks across Chromium, Firefox, WebKit, and mobile Chromium emulation, the production build passed, and all 58 Python tests passed.

## Unrecognized repair responses · 2026-10-27

Free-text repair exercises now distinguish exact accepted examples from other responses instead of mapping every unrecognized rewrite to a multiple-choice misconception. The app saves the learner's text for review without attaching a fabricated answer index, excludes it from mastery and assessment accuracy, and shows one verified example with the rule so a learner can compare without being told that a different valid sentence is wrong. Optional review fields preserve old backup compatibility. `make check` passed 340 engine tests, `make build-candidate` passed, and `make bundle` measured 84.9 KiB gzip against the 104.7 KiB initial-load budget. The focused Chromium browser assertion passed, including backup persistence and unchanged mastery; Playwright then hung during runner shutdown and had to be stopped, so this is not a full browser-suite pass.

The same-day development-only REALEC run covered 198 documents and 70,165 tokens: 165 true-positive, 722 unannotated predicted, and 4,556 missed annotated error tokens. Precision was 18.60% (Wilson 95% CI 16.18–21.30%), recall 3.50% (3.01–4.06%), total token misclassification 7.52%, missed-error rate 96.50%, and false-positive rate 1.10% (1.03–1.19%). This run was not used to tune the fixed test split or promote a detector. The independent test results remain 15.69% precision, 3.19% recall, 7.52% token misclassification, and 1.21% false-positive rate; none meets the requested limits. These corpus-overlap measures still do not establish goal-specific accuracy, valid-control false-positive rates, or acceptable corrections.

## REALEC token-classifier experiment · 2026-10-27

A project-local, development-only experiment trained a sparse token classifier on the document-separated REALEC training documents using token spelling, character affixes, and neighboring word and punctuation features. The classifier was scored against the unchanged 198-document development split (70,165 tokens; 4,721 annotated-positive tokens), using the browser evaluator's tokenizer. It was not merged with production findings, exported as a model, or evaluated on the fixed test split. This experiment tests whether more of the available corpus labels can be recovered with local supervised learning; it does not validate correctness against independent expert labels.

The best-recall threshold with false-positive rate below 1.21% found 258 of 4,721 annotated tokens (5.46% recall), with 788 false positives, 4,463 false negatives, 24.67% precision, 7.48% total token misclassification, and 1.204% false-positive rate. A threshold with 50% precision detected only 18 true positives and 18 false positives (0.38% recall), leaving 6.73% total token misclassification. The latter improves the aggregate error rate mostly by abstaining on nearly all tokens, so it is not useful tutoring coverage.

On this split, satisfying all three requested limits requires at least 2,004 true positives (42.45% recall), at most 791 false positives, and at most 3,508 total token errors. The experiment reached 258 true positives under the false-positive ceiling. It therefore fails the requested combination by a wide margin and was rejected. The held-out test remains untouched; production behavior and model assets remain unchanged. This confirms that another generic token-classifier threshold sweep is not a viable fix. Progress requires error-specific, writer-separated labels with adjudicated valid controls and usable correction targets; the current corpus includes broad discourse and wording annotations, lacks author identities, and does not establish that every annotation is a correctness error.
