# Isolated model development

All delivered assets, data, tooling, and caches reside inside this project. Frontend builds consume packaged artifacts and never train models or contact a corpus service.

```powershell
make train
make test-training
make check
make release
```

`make train` is the complete candidate pipeline. It ingests pinned data into the project, trains syntax models, prepares the classifier from frozen model predictions, checks exact Python/browser feature parity, trains the classifier, requires score parity against real browser ONNX inference, fits the contextual ranker, evaluates the oracle-feature reference, packages licensed resources, and evaluates quantization. It does not publish or replace the frozen release bundle. Review the candidate reports before promotion.

For an isolated classifier iteration after the syntax artifacts have been trained, run these steps in order:

```powershell
make prepare-errors
make seal-syntax-model
make check-classifier-features
make train-errors
make seal-classifier-model
make check-classifier-features ARGS="--scores"
```

Feature preparation defaults to one worker for predictable cross-platform execution; pass `ARGS="--workers 4"` to use parallel workers on a machine with available CPU and memory. The syntax manifest must be sealed before feature preparation, and the classifier manifest must be sealed before the score check. The feature check compares actual predicted POS tags, dependency heads, and numeric tensors from the browser runtime with the Python preparation path. The score check compares the newly trained ONNX model against browser WASM inference and binds its report to that exact weight file. Both checks write candidate-specific reports and leave frozen-release evidence intact. Training and packaging reject missing or stale evidence. Use the full `make train` pipeline when syntax weights or the lexicon have changed.

The delivered `.venv` uses `.tools/python`, has user-site disabled, and contains the dependencies pinned in `requirements.lock.txt`. Do not run global pip/npm installs. For an intentionally recreated environment, use a project-local Python runtime and `python -m venv .venv`, then install the lock with `./.venv/Scripts/python.exe -m pip install -r training/requirements.lock.txt` after setting project environment paths. Do not overwrite the supplied working environment unnecessarily.

`make ingest-training-data` verifies the pinned EWT r2.16 files, seven additional English UD evaluation treebanks, and the OANC GrAF archive. Atis, CHILDES, and ESLSpok training partitions contribute syntax-training sentences; their official test partitions are split-held-out, not source-held-out. Four other UD treebanks remain fully evaluation-only. The aggregate 100,028-token supplemental evaluation is dominated by CHILDES (52,497 tokens), so it must not be presented as independent written-prose validation. The written portions of OANC add more than 6,000 documents of local context counts to candidate ranking. OANC text is not treated as learner-error labels or gold POS/dependency annotation. All files are hash-pinned, fetched from immutable release URLs, and stored inside the project. GitHub-hosted files are fetched from raw URLs pinned to full commit IDs, never through the rate-limited GitHub API; transient HTTP failures and explicitly signaled rate limits honor retry headers, and verified local copies require no network access. Downloads are checked before atomic replacement. The model package retains the selected sources' license and attribution notices. Training keeps official split groups intact and excludes duplicate training sentences from held-out evaluation. Author and prompt independence remains unavailable. The SCOWL-derived dictionary is supplied with its pinned upstream manifest and complete notices; its raw files use the same offline-cache, digest-verification, and retry behavior, and packaging expands its PFX/SFX affixes.

The release trainer fits character CNN + bidirectional LSTM + CRF and an arc-standard transition MLP with bounded beam inference. Validation chooses the tagger checkpoint. The parser’s training states now use predictions from that frozen selected tagger, matching the predicted-POS input used at inference; its manifest records the train-split tagger accuracy and oracle-state counts. Test data do not fit vocabulary, parameters, calibration, or thresholds. The packaged lexicon retains complete UD FEATS; runtime morphology discards only `_` placeholder lemmas while preserving observed analyses. The error trainer derives agreement and perfect-form mutation labels from unique attested train-only paradigms; ambiguous and syncretic forms abstain. All classifier inputs come from the frozen predicted tagger/parser path. Platt calibration and threshold choice use separate validation document groups. Held-out component metrics are token-level controlled-task results before sentence caps and hybrid conflict handling. Neither those metrics nor the fixed-corpus production-worker probes establish accuracy on learner essays.

The contextual model uses a pruned interpolated Kneser–Ney bigram table and pairwise logistic correction ranking. The baseline script fits a sparse logistic classifier at a separately reported operating point. The quantization comparison evaluates actual float/int8 syntax models on the full held-out set; production remains float32 until browser parity and all relevant classifier gates are reviewed.

Output: `models/generated/ewt-1`; packaged browser assets: `apps/web/public/models`. Packaging preserves notices, generates and hashes a registry, checks declared syntax thresholds, and copies published ONNX Runtime WASM assets. Browser tests compare real emissions with Python fixtures and test failure/integrity/offline behavior. Run them after packaging and building.

Generic `train_tagger.py` and `calibrate.py` remain available for separately licensed JSONL datasets with explicit group splits. Do not ingest student writing without permission. BEA/FCE/LOCNESS resources have restrictions; [research notes](../docs/research-data-models.md) document the sources. Signing third-party agreements, human annotation, educator review, and learning trials require real authorized participants and are not fabricated by these scripts.

Measured production results and caveats are in the [model card](../docs/model-card.md), `reports/quantization-evaluation.json`, and the frozen model manifest. `reports/ranker-evaluation.json` is historical candidate evidence; the frozen `ewt-1` contextual resource contains no learned ranking coefficients. Candidate training evidence is kept separately in `reports/candidate-ranker-evaluation.json`, `reports/candidate-quantization-evaluation.json`, `reports/candidate-model-packaging.json`, `reports/candidate-classifier-baseline.json`, `reports/candidate-generalization-browser.json`, and `reports/secondary-ud-evaluation.json`; these reports do not replace production evidence or authorize promotion. The checkpoint manifest links the exact browser-path candidate report and records failed checks directly. Preserve all corpus and dictionary notices in any distribution.

`make generalization` evaluates the production browser worker against the fixed 300-sentence EWT fixture, authored development probes, and controlled agreement mutations; it does not train weights. The fixture spans five official EWT source genres and remains within-corpus evidence. The current production path measures all-gold POS/UAS/LAS of 93.50%/81.91%/77.81%. No classifier category currently passes the emission gate. The latest report also checks 411 cases and 229 edit proposals for source integrity. The browser fixture was inspected during tokenizer development, so refreshed scores are a reproducible regression measure rather than an untouched confirmatory estimate. See the [sampling, per-genre scores, and limitations](../docs/model-card.md#production-browser-generalization-check); synthetic coverage cannot replace independent learner-essay validation.

`make ingest-realec` downloads the hash-pinned REALEC archive into `.cache/datasets/realec/` and prepares fixed document-separated train, development, and test splits without extracting archive paths. `make evaluate-realec` builds the production app and runs the browser worker over the unchanged test split. The tracked report contains only aggregate token counts and recall by annotation label; essay text and IDs stay in the project-local cache. The source corpus is CC BY-SA 4.0, so retain attribution and share-alike terms for redistributed derivatives. The current 184-document test report has 15.24% token precision and 3.19% recall; author independence is unavailable, and the corpus is limited to Russian-L1 university essays. This binary span evaluation is a diagnosis aid, not validation for any of the 100 writing goals, valid-control false-positive rates, correction acceptability, or the broader learner population. Do not train or tune production behavior on the fixed test split. See the [manifest](datasets/realec-manifest.json), [independent evaluation](../reports/realec-independent-evaluation.json), and [model-card limitations](../docs/model-card.md#independent-learner-writing-benchmark).
